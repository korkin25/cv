# Правила для агентов в репозитории cv

## Что здесь лежит

- `CV_Devops_Ekuzakov.md` — резюме на английском, `CV_RU_Devops_Ekuzakov.md` — на русском.
  Обе версии меняются синхронно: правка в одной требует той же по смыслу правки в другой.
- PDF собирает GitHub Actions после push в `main` (`convert2pdf.sh`, только файлы `CV_*.md`).
  PDF вручную не правятся.
- `CV_Devops_Ekuzakov.telegram.txt` и `CV_RU_Devops_Ekuzakov.telegram.txt` — выдержки из резюме
  на одно сообщение Telegram, английская и русская.

## Текущий и прошлый стек

- Professional Summary (в русской версии — «Профессиональное резюме») и разделы выдержки
  «агентная разработка» и «платформенная инженерия» описывают только текущий стек: то, что
  используется в ISAIYA Health и на последнем месте работы.
- Инструменты прошлых мест работы упоминаются только в описании своего места работы и в
  таблице «Полный стек технологий». Например, Keycloak (SoftSwiss), OpenSearch (Latoken),
  SaltStack, Packer, Helmfile, Kaniko, а также MinIO, заменённый на Garage, в Professional
  Summary и в разделы навыков выдержки не попадают.
- В одном утверждении о текущем подходе нельзя соединять текущий и прошлый инструмент через
  «или» («Authentik или Keycloak»).

## Выдержка для Telegram

Обязательное правило: любой коммит, который меняет `CV_Devops_Ekuzakov.md` или
`CV_RU_Devops_Ekuzakov.md`, в том же коммите приводит обе выдержки в соответствие с резюме.
Английская выдержка строится только из английского резюме, русская — только из русского;
по составу пунктов они совпадают.

### Формат

- Обычный текст без разметки: файл вставляется в клиент Telegram как есть и отправляется
  через Bot API без `parse_mode`. Никаких `**`, `_`, `#`, `[текст](ссылка)`, таблиц и кода.
- Длина — не больше 3500 символов в единицах UTF-16 (лимит сообщения Telegram — 4096, запас
  оставлен на правки). Проверка:

  ```bash
  python3 -c 'import sys; [print(f, len(open(f, encoding="utf-8").read().encode("utf-16-le")) // 2) for f in sys.argv[1:]]' CV_*.telegram.txt
  ```

- Разделы по порядку:
  1. шапка — имя, должность, стаж, уровень английского, формат работы;
  2. агентная разработка;
  3. платформенная инженерия;
  4. опыт — по одной строке на место работы, от последнего к раннему, опыт до 2019 года
     одной строкой;
  5. контакты — email, Telegram, LinkedIn и ссылка на PDF своего языка.
- Заголовок раздела — строка, которая начинается с одного эмодзи; пункты начинаются с «• »;
  между разделами пустая строка.
- Ссылки — голыми URL, Telegram сам делает их кликабельными.

### Содержание

- Только факты из резюме, без новых утверждений и цифр. Формулировки сжимаются, смысл
  не меняется.
- Разделы «агентная разработка» и «платформенная инженерия» строятся из Professional Summary
  по правилу о текущем стеке; строка опыта берёт факты только из своего места работы.
- Выдержка не правится вручную в обход резюме: если в ней ошибка, исправляется резюме или
  это правило, а выдержка пересобирается заново.
- Без характеристик инфраструктуры (число нод, размеры ВМ), без ссылок на рабочие и внешние
  репозитории, без названия банка-заказчика.
- Если после правки резюме выдержка не влезает в лимит, сокращать ранний опыт и перечни
  инструментов, а не разделы про агентную разработку и платформенную инженерию.

## Публикация

Изменения не отправляются в GitHub (push) без явного согласования владельца.
